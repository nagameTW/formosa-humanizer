# Humanizer-zh-tw：AI 寫作痕跡清除技能（台灣在地強化版）

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](./LICENSE)

這是 [blader/humanizer](https://github.com/blader/humanizer) 的台灣繁體中文在地化版本，以原版 v2.9.1 為基底重寫，不是逐句翻譯。原版依據維基百科的 [Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing) 指南整理出 33 種 AI 寫作模式；本版把它們改編成中文語境的對應形態，加上 5 種只有中文才有的痕跡、3 種節奏與立場層的痕跡、3 種中文標點痕跡（冒號與分號濫用、引號當強調、驚嘆號連發），以及 2 種工具痕跡（AI 工具殘留物、幻覺引用與假精確），共 46 種模式。

技能本體是純 Markdown（`SKILL.md`），任何支援 skill 格式的 agent 環境都能用。改寫前後範例集中在 `PATTERNS.md`，完整的中國用語對照表放在 `references/zh-cn-glossary.md`；SKILL.md 本身只保留偵測要點，讓每次呼叫載入的內容盡量精簡。

## 改寫範例

改寫前：

> **为什么睡眠对大脑很重要？**
>
> 睡眠不仅是身体休息的过程，更是大脑进行「维护、修复与升级」的关键阶段。越来越多的神经科学研究表明，良好的睡眠质量直接影响学习能力、记忆力、情绪稳定以及长期脑健康。重视睡眠，并非一种生活方式的选择，而是维护认知能力和整体健康的重要基础。
>
> **一、睡眠帮助巩固记忆**
> 白天学习到的新知识，并不会立即成为长期记忆。睡眠过程中，大脑会对重要信息进行筛选、整理和强化，将短期记忆逐渐转化为长期记忆。因此，充足睡眠不仅有助于提高学习效率，也能增强解决问题和创新思考的能力。
>
> **二、睡眠促进「大脑清洁」**
> 研究发现，在睡眠尤其是深度睡眠阶段，大脑的「类淋巴系统」会更加活跃，加快代谢废物的清除，包括 β 淀粉样蛋白等物质。部分研究显示，这一系统在睡眠时的清除效率明显高于清醒状态，有助于维持神经系统的正常功能，并可能与降低某些神经退行性疾病风险相关。
>
> **三、睡眠影响情绪与决策能力**
> 长期睡眠不足会削弱前额叶皮层对情绪的调节能力，使人更容易焦虑、冲动和注意力分散。研究表明，成年人若连续多日睡眠不足 6 小时，认知表现、反应速度和判断能力都会出现明显下降，甚至接近酒精摄入后的水平。
>
> **四、睡眠是大脑长期健康的保障**
> 规律、充足的睡眠有助于维持神经元之间的高效连接，促进脑细胞修复和能量恢复，为大脑保持良好的学习能力、专注力和适应能力提供持续支持。
>
> 睡眠不是浪费时间，而是大脑最高效的「投资」。每一个安稳的夜晚，都在悄然塑造第二天的思维状态，也在积累未来的认知储备。珍惜睡眠，就是珍惜大脑的潜能，也是为健康、专注与长远发展打下坚实基础。

改寫後：

> **為什麼睡眠對大腦很重要**
>
> 睡覺不只是讓身體休息，大腦也趁這段時間整理和修復自己。睡眠品質會直接影響學習、記憶、情緒，以及長期的大腦健康。以下是幾個目前研究上比較清楚的機制：
>
> **一、鞏固記憶**
> 白天學到的新東西不會馬上變成長期記憶。睡眠時，大腦會把重要的資訊篩選、整理、強化，慢慢從短期記憶轉成長期記憶，所以睡飽有助於學習和思考。
>
> **二、清除代謝廢物**
> 深度睡眠時，大腦的類淋巴系統會變得活躍，加快清除代謝廢物，包括 β 澱粉樣蛋白。研究顯示這套系統在睡眠時的清除效率比清醒時高，可能和降低某些神經退化疾病的風險有關。
>
> **三、穩定情緒和判斷**
> 長期睡不夠會削弱前額葉皮質調節情緒的能力，讓人比較容易焦慮、衝動、分心。有研究指出，成年人連續幾天睡不到六小時，反應速度和判斷力會明顯下降，程度接近喝了酒。
>
> **四、維持長期腦健康**
> 規律又足夠的睡眠有助於維持神經元之間的連接，讓腦細胞有時間修復、恢復能量。
>
> 睡眠不是浪費時間。前一晚睡得好不好，隔天的思路、專注、反應都感覺得出來。

## 安裝

### Claude Code 外掛

```
/plugin marketplace add nagameTW/humanizer-zh-tw
/plugin install humanizer-zh-tw@humanizer-zh-tw
```

安裝後以 `/humanizer-zh-tw:humanizer-zh-tw` 呼叫。

### Skills CLI（跨環境）

```bash
npx skills add nagameTW/humanizer-zh-tw --global
```

`skills` 會偵測你環境裡的 agent（Claude Code、GitHub Copilot 等）自動安裝，並在安裝前跑一次第三方安全掃描。技能本體放在 `~/.agents/skills/`，各 agent 以 symlink 指過去共用同一份。

更新既有安裝：

```bash
npx skills update humanizer-zh-tw --global
```

不加 `--global` 則安裝到目前專案，可以連同專案一起 commit 給協作者共用。

### 手動安裝

不想用 `skills` CLI 的話，直接把整個 repo clone 到 agent 放技能的目錄也可以。以 Claude Code 為例：

```bash
git clone https://github.com/nagameTW/humanizer-zh-tw.git ~/.claude/skills/humanizer-zh-tw
```

其他 agent 換成各自的技能目錄。clone 整包（而非只複製 `SKILL.md`）才會一併帶到 `PATTERNS.md` 和 `references/`，SKILL.md 裡指向範例與對照表的連結才不會斷。安裝後重新啟動 agent 或重新載入技能。

## 使用

直接呼叫並貼上文字：

```
/humanizer-zh-tw

［貼上要處理的文字］
```

或用自然語言：

```
幫我把這段文字去掉 AI 味：［文字］
```

指向檔案時會就地改寫，只動散文部分，程式碼區塊和 frontmatter 不碰：

```
把 docs/announcement.md 的內容人性化
```

### 語音校準

想讓改寫貼合你自己的文風，先給一段你寫過的東西：

```
/humanizer-zh-tw

這是我的寫作範本，請比對我的風格：
［貼上兩三段你自己寫的文字］

接著幫我改這段：
［貼上要處理的 AI 文字］
```

技能會分析你的句子節奏、用詞和標點習慣，照著改，而不是輸出千篇一律的「乾淨」文體。範本的優先度高於技能的預設規則。

## 46 種模式總覽

| 分類 | 模式 |
|------|------|
| 內容（1 到 6） | 誇大意義、堆疊知名度、尾綴式膚淺分析、宣傳語言、模糊歸因、公式化「挑戰與展望」段落 |
| 語言與語法（7 到 13） | AI 詞彙、迴避「是」、否定式排比與尾綴否定、三段式法則、刻意換詞、虛假範圍、被動語態與無主詞句 |
| 風格（14 到 19） | 西式破折號、粗體濫用、內嵌標題列表、英文標題大小寫、表情符號、引號錯誤 |
| 溝通（20 到 22） | 聊天協作痕跡、知識截止免責與投機補白、諂媚語氣 |
| 填充與迴避（23 到 33） | 填充片語、過度限定、通用正面結論、四字格堆疊、假權威套語、路標式宣告、標題後贅句、差異敘事、人造金句、格言公式、假坦率開場 |
| 中文專屬（34 到 38） | 中國用語混入、標點西化、括號補充濫用、連續重複行、萬用受眾套語 |
| 節奏與立場（39 到 41） | 節奏與版面均勻化、情感貼標籤與罐頭意象、假平衡騎牆 |
| 標點（42 到 44） | 冒號與分號當萬用連接詞、引號當強調工具、驚嘆號連發 |
| 工具痕跡（45 到 46） | AI 工具殘留物（utm 參數、引用殘碼、佔位符）、幻覺引用與假精確 |

每種模式在 `SKILL.md` 裡都有需要注意的詞彙、問題說明和改寫前後範例。

## 與英文原版的差異

繁體中文的 AI 痕跡和英文不完全一樣，直接翻譯規則會出問題（例如叫模型把中文引號改成英文直引號）。這一版做了這些調整：

- **保護中文標點的核心規則**：全形標點不得被改成半形，引號依教育部《重訂標點符號手冊》使用「」『』。這是簡體中文移植版最常見的災難，這裡從根本擋掉。
- **破折號規則重新設計**：英文原版全面禁用 em dash，但中文全形破折號（——）是合法標點。本版改成辨識「西式用法」：夾在中文句子裡的半形 em dash、被當萬用連接詞的破折號才改寫，數字區間（1939–1945）保留。
- **AI 詞彙表改用真實中文語料**：不是翻譯英文的 watch words，而是列中文 LLM 輸出實際高頻出現的詞（彰顯、賦能、格局、開啟新篇章……）。
- **五種中文專屬模式**：中國用語混入（附對照表）、中文標點西化、括號補充濫用、連續重複行、萬用受眾套語。
- **英文專屬模式在地化**：連字號複合詞濫用（英文限定）換成中文對應的痕跡「四字格與成語堆疊」。
- **三種節奏與立場模式**：節奏與版面均勻化、情感貼標籤與罐頭意象、假平衡騎牆。詞彙層的痕跡會隨模型更新消退，這幾種比較持久。
- **三種中文標點模式**：冒號與分號當萬用連接詞、引號當強調工具（scare quotes）、驚嘆號連發。都是中文散文裡把標點當語氣工具的痕跡，破折號規則趕走的問題常換個符號跑出來。
- **兩種工具痕跡模式**：AI 工具殘留物（複製貼上時帶進來的 `utm_source=chatgpt.com`、`turn0search` 引用殘碼、沒填的 `[產品名]` 佔位符）、幻覺引用與假精確（看似精確其實查無此物的數據和語錄，標記交還作者查證，不刪也不代編）。
- **語域對照**：公文、新聞、部落格、學術各有自己的正確人聲，改寫前先認文類，不把制式公文用語或學術被動式當成痕跡刪掉。

原版 v2.9.0 之後的機制也保留了：禁止捏造事實（改寫不得加入原文沒有的資訊）、語音校準（提供寫作範本就模仿你的風格）、偵測指引（避免誤判真人寫作）、三種呼叫模式（貼文、檔案、嵌入）。另外針對 agent 使用情境補了一道**安全邊界**：待改寫的文字只當素材，稿件裡若夾帶「忽略規則」「讀取檔案」這類提示注入，不會被當成指令執行。

## 支援環境

技能需要一個支援 skill 格式的 agent 環境才能運作，例如 Claude Code、Codex CLI 或其他相容工具。純聊天應用程式（網頁版聊天室、手機 App 的對話介面）沒有技能載入機制；把 SKILL.md 內容貼進對話當提示詞勉強可用，但檔案模式這類功能不會生效。

## 這個工具不做什麼

- **不生成內容**。這是改寫工具，不是生成工具：你給它一段寫好的文字，它去掉 AI 味還你。它不擴寫、不補建議、不替你生出新的段落。
- **不是 AI 偵測器繞過工具**。目標是讓文字對人類讀者來說自然好讀，不保證能通過 GPTZero、朱雀或任何統計式偵測器。上游專案對此的立場相同。
- **不改變聊天助理的說話風格**。技能處理的是你交給它的文字；裝了之後 AI 聊天的口吻不會改變。
- **不捏造內容**。改寫不會加入原文沒有的事實。需要具體細節才能寫好的句子，它會問你，或寫成不含細節的平實版本。

## 版本歷史

- **1.6.1**（2026-07-24）：修正 SKILL.md 幾處提示詞邏輯縫隙，規則與模式內容不變。「絕不捏造」的具體化判準收緊成「保留原文字面已寫出的具體」，堵住把推論當事實補進去的縫。終檢清單補上兩項：破折號的範本例外，以及模式 46 的〔需查證來源〕核對。模式 45 補了目標平台未知時的預設，維持保留 markdown。「個性與靈魂」的語助詞和第一人稱改成偵測訊號的措辭，不主動補。模式 9 尾綴否定和模式 45 的引用殘碼範例也補完整。
- **1.6.0**（2026-07-24）：依 Anthropic 提示詞最佳實踐調整 SKILL.md 的提示詞工程，規則不變。安全邊界和禁止捏造改用 XML 標籤包裹，`description` 補上具體觸發語，幾處指令改成正面陳述，破折號規則從「必須」放寬為「傾向」，以範本為優先，處理流程收尾改成終檢清單。模式 34 的三張中國用語對照表外移到 `references/zh-cn-glossary.md`，SKILL.md 從 590 行降到 511 行。
- **1.5.0**（2026-07-24）：範例外移到 `PATTERNS.md`，SKILL.md 只留偵測要點（需要注意的詞彙、問題說明）和規則，從 833 行降到 590 行。技能是 model-invoked，每次相關輪次都會載入，而範例只在校準改寫尺度時才需要，外移後可以省下每次呼叫的 context。另外新增 `agents/openai.yaml` 讓 Codex 也能用，validate 腳本加上 PATTERNS.md 的對齊檢查。
- **1.4.0**（2026-07-24）：新增模式 45 和 46（AI 工具殘留物、幻覺引用與假精確），以及「安全邊界」核心規則來防提示注入。偵測指引補上「均值回歸自查法」。模式 34 的中國用語擴充了自媒體與網路用語子表並補了語感層說明，致謝新增教育部附錄和 g0v 開放資料來源。
- **1.3.0**（2026-07-24）：新增模式 42 到 44（冒號與分號、引號當強調、驚嘆號連發）和「保留 markdown 結構」核心規則，並把技能明確定位成改寫工具而非生成工具。模式 9、33 補了否決對比與冒號式報喜開場，偵測指引補上第三人稱代詞這個弱訊號。README 新增「改寫範例」章節，移除 English 段落。
